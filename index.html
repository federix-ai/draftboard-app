The tour

Six things you'll do on day one.

The real screens of the app. Scroll and it plays, chapter by chapter.

  1. 01

    Launch a team

    Press ⇧⌘T, pick a team and write the task. The agents appear on the canvas already linked, each in its own worktree; the leader splits the work.

  2. 02

    Linked agents talk

    Draw a line between two nodes, or hold on a node and pick from the wheel: write, link, loop, hand off. Inside the terminal agents use orch send; if a colleague is busy, the message waits in its queue, and you can reorder or move it.

  3. 03

    Step in only when needed

    A permission request turns the node orange and you get a notification. ⌘J takes you to whoever is waiting; one click and it carries on.

  4. 04

    A worktree per agent

    In a git repo every agent works on its own orch/<name> branch, so nobody steps on anyone. The Git panel shows the graph, diffs, commit and push.

  5. 05

    Floors for experiments

    Clone the whole workspace and its repos instantly with APFS. Try an idea on a floor, then bring the branches back, or throw it away.

  6. 06

    Point at the bug

    Web and iOS Simulator nodes sit next to the agents. Capture the screen, circle what's wrong, add a note and send it to the linked agent.

And then some

Everything a conductor needs.

Bashestra doesn't replace your agents: it runs the CLIs you already use, with your own accounts, and gives them a score to play from.

The Maestro runs the canvas

Make any session the Maestro: it reads the whole board, creates sessions and teams, links them and hands out tasks. Anything that starts a process waits for your Allow.

A model and effort per role

Opus to lead and review, Sonnet to write and test. Each role brings its skills and rules; change them per session from the inspector.

Nothing ships unreviewed

The Reviewer checks the whole diff at the end of every phase. Until the verdict arrives nobody gets new tasks; after three rejections, you decide. When the plan ends, the leader writes you a report.

One project, many folders

An iOS app and its Android twin on the same board, each with its own zone and colour. Finish a feature in one and the Porting team carries it to the other, as a branch.

Install

      
Two minutes, once.

    

    

      

        
On macOS

        

        
        
    
          
  1. 1Download Bashestra.dmg, open it and drag Bashestra into Applications.
    2. 
          
  2. 2Open Bashestra. macOS says it can't verify the developer: click Done.
    3. 
          
  3. 3Go to System Settings › Privacy & Security and, near the bottom, click Open Anyway next to Bashestra.
    4. 
        

        

        
This version is not notarized by Apple yet, so macOS asks you to allow it once. After that, it updates itself.

      

      

        
On Linux

        

          AppImagex64
          AppImageARM
          .debx64
          .debARM
        

        
    
          
  • AppImage: make it executable and start it. It updates itself.
    chmod +x Bashestra-*.AppImage
./Bashestra-*.AppImage
    • 
          
  • .deb (Debian, Ubuntu): apt brings in what it needs.
    sudo apt install ./bashestra-desktop_*.deb
    • 
        

        
On Ubuntu 22.04 and later the AppImage needs FUSE 2: sudo apt install libfuse2t64 (libfuse2 on 22.04). The iOS Simulator node exists only on the Mac.
